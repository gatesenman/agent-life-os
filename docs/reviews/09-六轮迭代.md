# 09 · 六轮自进化（v0.6.0）

操作者要求连续自主迭代六轮，代码由本项目自行演进。本轮在 0.5.0（记忆流、卡死自救、可观测性）之上交付 0.6.0，不改变 L1–L18「每步零违反」和「每笔支出必须人类批准」的约束。

## 方向取舍

预定六轮全部落地，没有替换。原因：0.5.0 已补齐心智与可观测性，产品上最明显的缺口正是「创世中心」命名不统一、社会层缺少对话、人类不能与虚拟人交谈、文明密度不够看得见、演示外卖必须手改饥饿、真实 VNC 付款缺少拦截说明。

## 第一轮 · 创世中心

原先「造宇宙、造地球、造人、造万物」的能力分散在右上角 God Mode、文明与环境的「世界法则 / 天启」、以及平行世界的分叉面板，侧栏里没有叫「创世中心」的入口。

本轮把这些能力收成一级导航：

- 侧栏「世界」分组新增「创世中心」，位于平行世界之前。
- 页面包含总览、宇宙与地球、世界法则、生灵、天启、分叉世界、见闻与对话。
- 总览用观察者口吻说明：改的是规则 R 或输入 h(t)，已发生的历史不会被改写。
- 为兼容既有端到端旅程，「文明与环境 → 世界法则」和「平行世界 → 分叉」入口全部保留，文案与按钮未改名。

涉及：`src/views/Genesis.jsx`、`src/components/Chrome.jsx`、`src/App.jsx`、`src/views/Multiverse.jsx`（导出分叉面板）。

## 第二轮 · 多智能体社交与信息传播

社会层原先有伴侣、冲突与合作，但居民之间没有对话，也没有可观察的信息流通。

本轮参考 AI Town / OASIS / Smallville：

- 居民按作息出现在同一地点时可能交谈。
- 见闻分为「事实」与「传闻」。传播时完整度衰减，低于阈值会变形并记为传闻。
- 灾害、疫病、科技、冲突等事件会成为可传播的事实。
- 涉及主角或重大传闻的对话写入生命大事记，带原因引用，满足 L3 因果。
- 只微调归属与喜悦（夹紧在 [0,1]，遵守 L16），不改金钱、人口和死亡。
- 使用独立于生育/死亡的随机流，既可复现（L6），也不扰动既有生命史测试。

40 年模拟：对话数十次，定律违反 0；同种子轨迹一致，快照恢复后再推进仍一致。

涉及：`core/life/society.js`、`test/social.test.js`。

## 第三轮 · 与虚拟人对话

观察舱原先只能看，不能和虚拟人说话。

- 在创世中心「见闻与对话」或「生命与家族」选择一位在世居民，以档案式谈话记录（不是即时通讯气泡）进行对话。
- 对话是人类输入 h(t)。对方会根据身份、饥饿、财富、见闻和信念作答。
- 若对象是主角，内容写入记忆流（重要度高，标签为「对话」），并可能出现在次日计划里。
- 已故之人不可交谈，直接拒绝（L8 必死律）。
- 对话不改钱包，事件带因果，校验 L1–L18。

涉及：`core/engine.js` 的 `talkTo`、`core/memory.js`、`src/components/TalkPanel.jsx`、`electron/main.js`。

## 第四轮 · 文明与社会密度

文明页已有卡尔达肖夫、科技树和制度仪表，但缺少「这座城市有多密、消息传得快不快」的可见结构。

- 地点按坐标聚合成街区，统计在场人口与公共机构（医院、学校、文化中心）。
- 新增观察量：识字率（平均教育）、城镇化、信息流通、社会资本、地点密度。
- 这些量写入年度历史，进入文明页与创世中心，作为公式 F 的观察输出，不另立会破坏既有校验的新定律。

涉及：`society.districts` / `refreshCivic`、`src/views/Civilization.jsx`、创世中心生灵页。

## 第五轮 · 演示与电脑操作加固

演示点外卖时，端到端测试曾直接改写 `hunger`。这与 L17（饥饿只随世界时间上升）的精神不符，也不方便操作者在界面里触发场景。

- 新增 `fastForwardHunger`：只调用世界时钟的 `advance`，饥饿按 0.05 / 小时上升，社会层同步推进。不改钱包，不代替智能体下单。到达约 72% 后，回到智能体桌面即可看到 TA 自己去点外卖并申请审批。
- God Mode 下，创世中心「天启」页和智能体桌面工具栏都有「快进到饥饿」。
- 支付拦截：内置沙盒的「提交订单并支付」本来就只发起审批、批准前不扣款。对 VNC，若思考/屏幕/目标含有支付语义，系统会把即将发出的点击改写成 `request_payment`，待批期间不再向虚拟机发送可能完成付款的操作。
- 拦截依据是当前思考、屏幕文字和步骤（如「确认支付」「submit」），不会因为目标说明里写了「付款前必须申请审批」就把「加入购物车」误拦。
- **限度（必须写明）**：协议层无法阻止真实虚拟机内部已经完成的支付（例如机内浏览器已向商户提交订单）。绑定真实电脑时，只应使用测试卡、演示账户或额度极低的卡，不要绑定含个人支付账户的机器。

涉及：`core/engine.js`、`core/desktop/session.js`、`src/views/Desktop.jsx`、`test/desktop.test.js`。

## 第六轮 · 打磨、测试与发布

- 单元测试：社交/对话/可复现、快进到饥饿、VNC 支付拦截；既有 life / desktop / multiverse / memory / no-emoji 保持通过。
- 端到端新增：打开创世中心、与主角对话并检查记忆、快进到饥饿；长跑页面列表加入创世中心。原有 35 步旅程（引导、外卖批准/拒绝、法则、天启、分叉、镜像、续存、孵化、VNC）保持不变。
- 版本号 0.6.0；中文更新说明写入 README；界面仍只用 lucide 字体图标，无 emoji。

## 风险与未验证项

- 真实 Windows 上的 GPU 性能、SmartScreen 提示，仍未在本轮验证。
- 真实视觉模型驱动 VNC 下单，仍依赖操作者自己的 `OPENAI_*` 配置。
- QEMU / VirtualBox / UTM 作为绑定目标，仍未实测。
- 支付拦截对真实虚拟机是尽力而为，不是技术上的绝对拦截。
- Stripe Issuing、AgentMail、Twilio 仍需操作者自己的账号，本轮未对真实服务回归。



## 端到端结果

- 单元测试：life（500 年 0 违反）、social、memory、desktop（含快进、支付拦截与真实 VNC）、multiverse、no-emoji 全部通过。
- 端到端 Playwright：新增创世中心、与主角对话、快进到饥饿后共 38 步。最终一次 **38/38 全绿**，定律违反 0，无崩溃、无页面异常、无 emoji。
- 10 分钟长跑做过两轮（在修复 VNC 误拦截之前），均为违反定律 0、内存未持续增长（约 1200 MB → 1000 MB）。最终全绿跑使用 1 分钟长跑以复验 VNC 路径。
- 首次全量长跑后的第三次启动曾因机器磁盘紧张导致 Electron 二进制被清掉而中断，与产品逻辑无关。
