## 2. 测试环境与方法

- 环境：Linux 盒子，Electron 33.4.11，独立 Xvfb 显示器（1600×1000），使用软件 WebGL（没有 GPU）。
- 用户数据：每次运行都用全新的临时目录（`ALOS_USER_DATA`、`ALOS_DATA_DIR`），保证是“第一次打开应用”。
- 节奏：`ALOS_TICK_MS=300`，比默认的 1500ms 快 5 倍，用来加压。
- 模拟“时间流逝”：为了不用真等几个小时让 TA 饿，测试通过只在 `ALOS_E2E=1` 时才开启的主进程钩子，把饥饿值直接设为 72–75%。之后的打开外卖、下单、审批，全都由智能体自己完成，或者由测试点击界面完成。
- 视觉模型：VNC 阶段用本地模拟的 OpenAI 兼容服务。它收到的是**真实的 VNC 截图**，返回坐标点击和付款申请。
- 真实 VNC：`scripts/vnc-demo.sh`，即 Xvfb `:57` + Chrome 演示网页 + x11vnc（端口 5957，设有密码）。
- 健康监测：
  - 监听渲染进程的 console error、pageerror、crash；
  - 每个页面检查是否有没绑定处理函数的按钮、是否出现 undefined/NaN/[object Object]、是否有英文残留、是否有没退出的动画层；
  - 长跑期间每 30 秒采样一次进程树的 RSS 和 CPU（读 /proc），以及主进程和渲染进程的 JS 堆。

### 关于“创世中心”

应用里没有叫“创世中心”的页面。它对应的功能是：右上角开启 **God Mode** → **文明与环境 → 世界法则**（改寿命上限、疫病率等规则 R）和 **天启**（瘟疫、天灾等事件），以及 **平行世界** 页的分叉。本次测试覆盖的就是这些入口。

## 5. 长跑（10 分钟，300ms 节奏）

- 步数：9 → 2006。定律违反 0，崩溃 0，控制台错误 0。
- 每 30 秒轮换一个页面（概览、桌面、镜像世界、活动、平行世界、生命与家族、文明与环境、收支），一共 20 次。
- 主进程 JS 堆在 9–23 MB 之间波动，渲染进程 JS 堆稳定在 21 MB，**没有看到 JS 内存泄漏**。
- 进程树 RSS 在 915–1384 MB 之间波动，末段偏高。主要是软件 WebGL（3D 镜像世界和头像）的缓冲区，不是 JS 堆。有 GPU 的真机会不同，见第 7 节。
- CPU：平均 215%（100% = 一个核）。每轮切到镜像世界时峰值约 650%，因为 Xvfb 下 three.js 走 CPU 软件渲染，而且节奏是默认的 5 倍。
- 长跑期间模拟守护者离开，没有批准任何订单：TA 一直等待审批，没有扣款。

## 7. 无法在本机验证的内容 / 剩余风险

- **真实 Windows 10/11**：wine 不等于真实 Windows。以下需要在你的电脑（SD-20250722DZPD）上手动确认：
  - SmartScreen 提示（安装包没有代码签名，会提示“未知发布者”，属于预期）；
  - 开始菜单和桌面快捷方式；
  - 卸载；
  - Windows 原生标题栏按钮；
  - GPU 下的 3D 帧率。
- **真实视觉大模型**：VNC 阶段用的是模拟视觉模型（截图和坐标链路是真的，“看懂屏幕”的部分是脚本）。接入真实 OpenAI 兼容视觉模型后，点击准确率没有测过。
- **QEMU / VirtualBox / UTM**：只验证了 x11vnc（RFB 3.8，VNC 密码认证）。
- **CPU / 内存**：在 GPU 真机和默认 1500ms 节奏下应明显更低，但没有实测；软件渲染下镜像世界页很耗 CPU。
- **续存格式**：`multiverse.json` 是第一版格式（version 1）。0.4.1 升级到 0.4.2 后第一次启动会重新创世（0.4.1 没有存档可恢复）。
- **英文残留（保留）**：设置页的 DNA 原始 JSON 字段名、OSM 地名、沙盒网址（waimai.sandbox）、按键名（Enter、ctrl）、档案卡上的 FICTIONAL / NOT A GOVERNMENT ID 水印，这些都是有意保留的。
- **饥饿上升用了测试钩子加速**，没有真的等几个小时。按日常节奏，饥饿到 60% 大约需要 8–10 个世界小时。
