# 06 行业竞品分析（v0.5.0）

> 日期：2026-10-22（北京时间）。目的：找出「虚拟人生 / Agent Life OS」在同类产品中的位置，以及最值得借鉴的能力。
> 外部数据来自公开论文、官方文档和公开排行榜（OSWorld Verified，2026-10-21 数据）。这些数据只用于定位，没有在本产品中复现。

## 1. 竞品地图

我们处在三条赛道的交汇处，目前没有一家同时覆盖三条：

| 赛道 | 代表产品 | 核心价值 | 与我们的关系 |
|---|---|---|---|
| A. 智能体社会模拟 | Stanford Generative Agents（Smallville）、a16z AI Town、Altera Project Sid、Fable Showrunner、The Sims | 让一群角色"像人一样生活"，可观察、可涌现 | 我们的"生命与家族 / 文明 / 平行世界"属于这条赛道 |
| B. 陪伴与角色 | Character.ai、Replika、Inworld | 有人格、有记忆的角色，能长期互动 | 我们的"DNA → 人格 → 人生故事"属于这条赛道 |
| C. 电脑操作智能体（Computer-Use） | Anthropic Computer Use、OpenAI Operator / ChatGPT Agent、Manus、Simular、UI-TARS 桌面版 | 看屏幕、动鼠标，替人完成真实任务 | 我们的"智能体桌面（沙盒 / VNC 第一人称）"属于这条赛道 |

**我们的独特点**：同一个角色既在"社会里活着"（会生老病死、遗传、文明演进），又在"电脑上干活"（第一人称操作一台指定电脑，例如点外卖），而且有一套可校验的世界定律（L1–L18），人类在外面观察、审批每一笔支出。

## 2. 逐个分析

### 2.1 Stanford Generative Agents（Smallville，2023）
- **能力**：25 个角色的小镇，自发组织情人节派对。
- **架构**：记忆流（memory stream）、检索、反思、计划，四件套。
  - 记忆流：所有观察都带时间戳和重要度。
  - 检索：得分 = 新近度 + 重要度 + 相关度。
  - 反思：累计重要度超过阈值就归纳出更高层的洞见。
  - 计划：先排一天的粗计划，再逐级细化。
- **体验**：2D 像素小镇，可以点角色看当前在做什么。
- **我们的差距（v0.4.2）**：只有"短期 + 日记 + 教训"，没有重要度、检索打分、反思和日计划。→ **第一轮进化补齐。**

### 2.2 a16z AI Town（开源，见 07）
- 基于 Generative Agents 的工程化版本：tick 驱动的游戏引擎，人和智能体都通过 input 改状态，LLM 调用异步执行。
- **值得学**："智能体同一时间只做一件事（inProgressOperation）"。我们已有 busy 锁，思路一致。

### 2.3 Altera Project Sid（2024）
- **规模**：Minecraft 里 10–1000+ 个智能体，涌现出职业分工、税法投票、宗教与文化传播。
- **架构 PIANO**：多个模块并发运行（记忆、行动觉察、目标生成、社交觉察、说话、技能执行），由一个"认知控制器"做瓶颈决策，避免说的和做的不一致。
- **值得学**："行动觉察（Action Awareness）"，也就是对比预期和实际结果，发现自己卡住了。→ **第二轮进化：卡死检测与自我纠偏。**

### 2.4 The Sims
- **能力**：需求（饥饿、精力、社交……）驱动的自主行为，加上"上帝之手"。
- **体验标杆**：一眼能看到角色"为什么"做这件事（需求条和念头气泡）。
- 我们已有饥饿、能量、心情、马斯洛需求和思考流。**可借鉴**：可解释性要再前置。→ 第三轮的可观测性面板。

### 2.5 Fable Showrunner / Inworld / Character.ai / Replika
- 强项在人格一致性、长期记忆和对话质量。Inworld 把角色拆成"大脑 / 记忆 / 目标 / 情绪"可配置模块。
- **我们的差距**：缺少和角色直接对话的入口（只能下"指令"）。列入后续路线图，本轮不做。

### 2.6 Anthropic Computer Use / OpenAI Operator / Manus / Simular
- OSWorld Verified（2026-10-21）：头部智能体成功率已超过 80%（例如 Intelligence-Indeed Agent 90.19%）；Agent S3（bBoN）约 72.6%；UI-TARS-2 约 53%。
- **共识做法**：
  1. 截图 → 动作 → 再截图校验；
  2. 敏感操作（付款、登录）交还人类确认，例如 Operator 的 takeover；
  3. 步数预算与卡死恢复；
  4. 完整轨迹回放。
- **我们已具备**：截图校验、付款审批、接管、录像回放。
- **我们缺少**：①检测"同一动作在同一屏幕上反复无效"的循环；②单个目标的步数预算；③可靠性指标（成功率、校验通过率、恢复次数）。→ **第二轮补齐。**

## 3. 结论：优先级

| 优先级 | 借鉴点 | 来源 | 落地轮次 |
|---|---|---|---|
| P0 | 记忆流 + 检索打分 + 反思 + 日计划 | Smallville / AI Town | 第一轮 |
| P0 | 卡死 / 循环检测、步数预算、可靠性指标 | Project Sid 行动觉察、Operator、OSWorld 类智能体 | 第二轮 |
| P1 | 运行可观测性：每步耗时、决策来源、校验率、定律检查 | The Sims 的可解释性、LangSmith / AgentOps 类工具 | 第三轮 |
| P2 | 与角色直接对话、多智能体之间的社交对话 | Character.ai / AI Town | 路线图 |
| P2 | 真实视觉模型的效果评测（OSWorld 风格任务集） | OSWorld | 路线图（需要用户的模型密钥） |
